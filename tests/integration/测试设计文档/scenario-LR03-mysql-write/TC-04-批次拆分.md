# TC-04 批次拆分

## 用例编号与名称

TC-04 批次拆分（`TestLR03_BatchSplit`）

## 所属场景

LR03 MySQL 写入场景（scenario-LR03-mysql-write）

## 版本声明

- `log-reader`：当前源码版本（含 `mod_log_mysql` 模块）

## 测试目的

验证日志量超过读侧 `MaxSizePerBatch` 与写侧 `BatchSize` 时，模块能正确拆分批次处理：读侧按 `MaxSizePerBatch` 切分 Update 批次，写侧按 `BatchSize` 攒批 flush，全程不丢行、不串值。

## 运行模式

单组件模式：真实 `log-reader` 进程 + 真实 MySQL。

## 前置条件

同 TC-01。

## 配置构造

- `config.conf`：`MaxSizePerBatch = 10`（25 条日志被拆为 10/10/5 三个 Update 批次）。
- `mod_log_mysql.conf`：`BatchSize = 5`（写侧至少 5 个 INSERT 批次）、`FlushIntervalMs = 200`。

## 输入数据

25 条 `common.MakeRequestLog` 日志：`logid = 90001..90025`，`ai_requested_model = batch-model-00..batch-model-24`（模型名逐条不同，保证唯一键互不冲突——唯一键含模型名列，同模型日志会合并为 1 行）。

## 操作步骤

1. 准备环境并启动 `log-reader`。
2. 连续写入 25 条 b2log 记录。
3. 轮询等待表行数 ≥ 25（超时 30s）。
4. 精确断言行数 = 25。
5. 查询 `logid BETWEEN 90001 AND 90025` 的全部行，断言 logid 集合齐全且每条行的 `ai_requested_model` 与 logid 序号对应。

## 预期结果

- 表内恰好 25 行，无丢失、无重复。
- 每条行的 `ai_requested_model` 正确（验证多批次处理下各行映射不串）。

## 清理

停止 `log-reader` 进程，关闭数据库连接，DROP 测试专用数据库，删除临时目录。
